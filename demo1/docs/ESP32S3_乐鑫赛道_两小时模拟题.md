# ESP32-S3 乐鑫赛道两小时模拟题

## 一、测评说明

1. 本题为全国大学生嵌入式芯片与系统设计竞赛乐鑫赛道模拟测评题。
2. 测评时间为 2 小时。参赛者应在规定时间内完成全部功能，并现场演示验收。
3. 本题不要求使用 OLED。运行状态通过普通 LED、可编程全彩 LED、蜂鸣器和上位机串口进行显示或反馈。
4. 题目各小题具有递进关系，后续功能应在前面功能的基础上继续完善，不得破坏已经实现的功能。
5. 除题目明确要求外，不规定具体的软件结构。参赛者应保证程序运行稳定，不得因长时间阻塞导致其他功能失效。

## 二、硬件条件

开发板应至少具备以下硬件资源：

1. 四个普通 LED，编号为 LED1、LED2、LED3、LED4。
2. 一个 GPIO 按键，按下时产生稳定的按键事件。
3. 一个可连接导电片的 Touch 输入通道。
4. 一颗或多颗 WS2812 类可编程全彩 LED。
5. 一个有源蜂鸣器和一个无源蜂鸣器。
6. 一路 ADC 模拟量输入，用于连接可调电阻或模拟传感器。
7. 一路与上位机通信的 UART 串口。
8. 至少 1 KB 的 NVS 非易失性存储空间。
9. 一个可产生周期事件和单次事件的硬件定时器。

本工程示例引脚如下：普通 LED 使用 GPIO1、GPIO2、GPIO4、GPIO5；有源蜂鸣器使用 GPIO6；无源蜂鸣器使用 GPIO7；按键使用 GPIO8；ADC 使用 GPIO9；WS2812 使用 GPIO11；Touch 导电片使用 GPIO14；外部 UART 使用 GPIO17 和 GPIO18。若实际开发板引脚不同，以开发板原理图为准调整配置。

## 三、功能要求

### 第 1 题：上电初始化和定时显示

系统上电后，应完成所有外设初始化。

上电初始状态如下：LED1 和 LED3 点亮，LED2 和 LED4 熄灭，可编程全彩 LED 显示蓝色，有源蜂鸣器关闭，无源蜂鸣器鸣叫 100 ms。系统进入初始状态后保持 10 秒。

10 秒到达后，四个普通 LED 全部点亮，可编程全彩 LED 改为绿色，无源蜂鸣器停止鸣叫，并通过 UART 向上位机发送“BOOT OK”。

10 秒等待必须由定时器事件完成，不能使用会长期占用任务的阻塞延时实现。

### 第 2 题：按键模式切换

按键采用中断方式检测。无论按键保持按下多长时间，一次按下只能产生一次有效事件；按键释放后才能识别下一次按下。程序必须具备基本消抖能力。

每次按键按下，模式变量 mode 按 0、1、2、3、0 的顺序循环切换。

四种模式的显示要求如下：

1. mode 为 0 时，四个普通 LED 和全彩 LED 全部熄灭。
2. mode 为 1 时，仅 LED1 点亮，全彩 LED 显示红色。
3. mode 为 2 时，仅 LED2 点亮，全彩 LED 显示绿色。
4. mode 为 3 时，仅 LED3 点亮，全彩 LED 显示蓝色。

每次模式切换时，无源蜂鸣器以 1000 Hz 鸣叫 100 ms，并通过 UART 发送当前模式值，格式为“MODE=n”。

### 第 3 题：Touch 亮度控制

使用 Touch 导电片检测触摸按下和释放状态。触摸按下时只能产生一次有效事件，手指持续接触导电片期间不得重复触发。

每次有效触摸在亮度 32 和亮度 128 之间切换。亮度改变后，全彩 LED 应立即显示新的亮度；无源蜂鸣器以 2000 Hz 鸣叫 100 ms；UART 发送当前亮度，格式为“BRIGHT=n”。

### 第 4 题：UART 接收和远程控制

上位机通过 UART 向下位机发送以下命令：

1. 发送“GET”，下位机返回当前模式、亮度、ADC 百分比和系统状态。
2. 发送“MODE n”，其中 n 为 0、1、2 或 3，下位机立即切换到指定模式。
3. 发送“BRIGHT n”，其中 n 为 32 或 128，下位机立即修改全彩 LED 亮度。

命令执行成功返回“OK”；命令格式错误或参数超出范围返回“ERROR”。串口接收过程中不得影响按键、Touch 和 ADC 功能。

### 第 5 题：ADC 采样和变量显示

使用 ADC 周期采集模拟输入电压，采样周期为 200 ms。每次采样应获得 ADC 原始值和换算后的输入电压值。

定义变量 aa 表示当前模拟量百分比，计算方式为：输入电压与 3.3 V 的比例换算为 0 到 100 的整数。aa 不得小于 0 或大于 100。

每隔 1 秒通过 UART 发送一次当前采样结果，格式如下：

“AA=xx MV=xxxx STATE=NORMAL”

其中 xx 为 aa，xxxx 为输入电压毫伏值。若系统处于报警状态，STATE 应改为 ALARM。

### 第 6 题：超限报警和事件联动

当 aa 大于或等于 80 时，系统进入报警状态；当 aa 小于或等于 70 时，系统解除报警状态。70 到 80 之间保持当前状态，防止输入在临界值附近波动造成频繁切换。

报警状态下：

1. 全彩 LED 强制显示红色。
2. LED4 按 500 ms 周期闪烁。
3. 有源蜂鸣器打开。
4. UART 状态字段为 ALARM。

报警解除后：

1. 有源蜂鸣器关闭。
2. LED4 恢复为常亮。
3. 全彩 LED 恢复报警前的 mode 和 brightness 显示。

报警显示的优先级高于普通模式显示，但不得修改用户保存的模式值和亮度值。

### 第 7 题：NVS 掉电保存

系统应将 mode 和 brightness 保存到 NVS 中。模式切换或亮度修改成功后，应立即更新对应数据。

系统重新上电时，应从 NVS 中读取 mode 和 brightness，并恢复上次断电前的显示状态。

如果 NVS 中没有对应数据，或者读取到的数据超出有效范围，应使用以下默认值：mode 为 0，brightness 为 32。

报警状态和 ADC 当前采样值不要求保存。重新上电后，系统应重新进行 ADC 采样并根据当前输入判断是否报警。

## 四、现场验收要求

1. 上电后能够观察到规定的初始 LED、RGB 和蜂鸣器状态。
2. 10 秒定时事件到达后，系统能够自动切换到上电完成状态。
3. 按键长按只能切换一次模式，释放后再次按下才能切换下一次。
4. Touch 长按不能重复改变亮度。
5. UART 命令能够正确控制模式和亮度，并返回规定的结果。
6. ADC 输入低于解除阈值时系统正常，超过报警阈值时系统报警。
7. 报警状态能够覆盖普通灯光显示，报警解除后能够恢复原模式。
8. 修改 mode 和 brightness 后重新上电，系统能够恢复断电前的值。
9. 任意功能运行时，其他功能不能停止响应或导致系统复位。

## 五、建议验收顺序

先验收上电初始化和定时器，再验收按键与 Touch，随后验收 UART，最后改变 ADC 输入验证报警逻辑，结束时断电重启验证 NVS 保存结果。
